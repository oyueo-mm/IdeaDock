# 검증 기록

검증일: 2026-10-27 (Asia/Seoul)

## 최종 두 세션 동기화 및 배포 준비 검증

최종 로컬 결과: 단위·회귀 **52/52**, 타입 검사·빌드 통과, 기본 Playwright **16개 통과**(전용 모의 Drive 4개는 이 명령에서 제외), 별도 모의 Drive Playwright **4/4 통과**입니다. 52개에는 서버 이력 캐시 1개와 Preview 배포 경계 보호 2개 회귀 테스트가 포함됩니다.

서로 다른 브라우저 컨텍스트 두 개를 같은 Google 계정으로 연결했습니다. 앱의 액세스 토큰과 IndexedDB는 분리했고 실제 Drive API로 아래 항목을 실행했습니다.

| 항목                | 실제 결과                                                                                                                                                                    |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 생성·수정·완료·태그 | A 생성 → B 조회, B 본문·완료·태그 수정 → A 반영 통과                                                                                                                         |

| 동시 수정           | B가 이전 버전에서 초안 작성 중 A가 먼저 저장. B 재연결 시 충돌 검출. 원본과 초안 복사본을 각각 저장하고 A에서도 두 내용을 조회함. 이미지 참조 유지                           |

| 기존 체험 데이터    | 두 검증 프로필에 체험 데이터 0개, 실행 전후 값 동일. 다른 프로필 전체를 조사한 결과로 간주하지 않음                                                                          |
| 전달받은 URL        | 해당 아이디어는 두 번째 독립 세션에서도 Drive에서 조회됨. 중복 이전 대상에서 제외                                                                                            |
| 복구 백업           | 현재 Drive 아이디어 4개와 이미지 원본 1개를 로컬 복구 JSON에 저장, 이미지 SHA-256 일치. 사용자가 전달한 대상도 포함. 이후 생성한 검증용 복사본 등과 시점 차이가 있을 수 있음 |
| 실제 이전           | 확인된 체험 이전 대상 0개. 사용자 승인 없이 이전·삭제하지 않음. Supabase 이전은 사용자 확인에 따라 생략                                                                      |

실제 검증에서 각 조회·저장마다 전체 이력을 다운로드해 지연되는 원인을 발견했습니다. 검증된 불변 이력을 계정·저장 공간·해시별로 IndexedDB에 캐시하도록 수정했습니다. 일반 조회도 매번 Drive 파일 목록을 조회하므로 새 이력을 발견합니다. 이전 완료 검증은 `revisions(true)`로 서버를 강제 재조회하며 캐시 성공을 서버 검증으로 대체하지 않습니다. 이 동작과 원격 손상 검출 테스트를 추가하여 **단위·회귀 50/50개와 타입 검사·빌드 통과**를 확인했습니다. 수정 후 실제 두 세션에서도 재인증·수정·상대 세션 조회와 오류 없음까지 재확인했습니다.

Google 계정 간 실제 격리, 실제 두 물리적 기기, Safari/WebKit, 장시간 오프라인·토큰 만료·모바일 절전 복귀는 미실행입니다. [인증 UX 비교와 실기기 확인 목록](RELEASE_READINESS.md)에 별도로 기록합니다. 이 결과를 장기 오프라인 또는 자동 병합 보장으로 해석하지 않습니다.

자격 증명 없는 요약 보고서와 백업·이전 미리보기는 Git 제외된 `.local/`에 보관합니다. Vercel Preview의 정확한 URL과 최종 Git 커밋은 배포 준비 완료 후 [릴리스 준비](RELEASE_READINESS.md)에 기록합니다.

### Vercel 배포 결과와 제한

Preview 환경 설정과 업로드 제외 검사는 완료했습니다. 명시적 Preview 배포 명령이 Vercel에서 Production으로 분류되어 생성된 배포 하나를 즉시 삭제했습니다. 활성 배포 0개를 확인했고 반복 시도하지 않았습니다. 따라서 **Preview URL 확정·Preview 로그인·HTTPS 실기기 검증은 미실행**입니다. 삭제한 Production 시도가 전혀 없었던 것으로 기록하지 않습니다. 빌드 전 Preview 환경 보호 장치를 추가했고 상세 원인·복구·다음 조건은 [릴리스 준비](RELEASE_READINESS.md)에 기록했습니다. main 병합과 Google Drive 데이터 변경은 이 복구 작업에 포함되지 않습니다.

## 실제 Google Drive 연결 검증 완료

사용자가 `.env.local`에 Client ID 입력을 완료했습니다. 값 자체를 출력하지 않고 설정 여부와 형식만 확인했습니다. `NEXT_PUBLIC_STORAGE_BACKEND=drive`, 일반 Drive 공간 사용, Supabase 환경변수 미설정을 확인했습니다. 사용자가 Supabase를 실제 연결한 적이 없다고 확인했으므로 Supabase 서버 이전은 생략합니다. 미설정 상태를 빈 서버 조회 결과로 기록하지 않습니다.

기존 IdeaDock 개발 서버의 실행 경로와 프로세스를 확인한 뒤 재시작하여 새 환경변수를 적용했습니다. `http://localhost:3000`은 HTTP 200이며, 별도 Edge 검증 프로필에서 실제 Google 로그인 창을 열었습니다. 이 프로필의 체험 캐시와 기존 IndexedDB는 0개이며, 사전 조사 결과를 Git 제외된 `.local/`에 로컬 백업했습니다. 다른 브라우저 프로필의 체험 데이터를 삭제하거나 이전하지 않았습니다.

사용자가 Google 로그인 및 권한 동의를 완료한 후 **실제 Google API에 연결하여 검증했습니다. 모의 OAuth/Drive를 사용하지 않았습니다.**

| 항목                 | 실제 검증 결과                                                                                                                       |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Google 로그인        | 앱에서 Google 계정 연결 상태 확인, 실제 Drive 조회 HTTP 200                                                                          |
| IdeaDock 폴더        | 일반 Drive 폴더 1개 확인. 이름·폴더 MIME·앱 소유 마커 일치, 휴지통 아님. 폴더 메타데이터 및 자식 목록 조회 HTTP 200                  |
| 테스트 아이디어 생성 | 별도 테스트 제목으로 새 아이디어 추가, Drive의 버전 1 문서 다운로드와 내용 일치 확인                                                 |
| 수정                 | 제목·본문·완료 상태·`drive-live-check` 태그 변경. 실제 업로드 POST/PUT HTTP 200, 버전 2 문서 재조회 일치                             |
| 파일 무결성          | 이번 테스트 아이디어의 실제 이력 파일 2개(버전 1, 2)를 식별하고 각각 SHA-256과 저장된 해시 일치 확인. 기존 다른 문서는 변경하지 않음 |
| 새로고침             | 페이지 새로고침 후 같은 계정으로 재인증. 실제 서버에서 수정된 제목·본문·완료·태그를 다시 읽고 화면 일치 확인. 폴더 개수는 1개 유지   |
| 기기 저장            | IndexedDB에 테스트 아이디어 존재, 미저장 pending 0개                                                                                 |
| 체험 데이터          | 검증 프로필의 `ideadock:data:*` 값이 실행 전후 동일. 체험 데이터 이전·삭제 미수행. 다른 브라우저 프로필의 데이터는 이번 검증 범위 밖 |
| Supabase             | 사용자 확인 및 환경변수 미설정에 따라 서버 이전 생략. 실제 빈 서버를 조회했다는 의미는 아님                                          |
| 오류                 | 실제 API 실패 응답 및 앱 오류 배너 없음                                                                                              |

검증 도중 브라우저 자동화 도구의 응답 본문 수집이 빈 값으로 반환되는 문제가 있었습니다. 앱의 실제 브라우저 `fetch` 응답을 복제하여 검사하는 방식으로 변경한 뒤 서버 내용과 체크섬을 확인했습니다. 서버 응답을 모의로 대체하거나 수정하지 않았으며 앱 저장 코드 수정은 필요하지 않았습니다.

현재 인증 토큰은 메모리에만 보관하므로 **새로고침 후 Google 재로그인이 필요합니다. 데이터는 Drive와 IndexedDB에 보존됩니다.** 이번 검증은 동일 브라우저의 새로고침 및 동일 계정 재조회이며, 두 물리적 기기의 동시 편집·기존 데이터의 실제 마이그레이션·운영 배포 검증을 의미하지 않습니다.

테스트 아이디어는 제목이 `IdeaDock 실제 연결 검증 … · 수정 확인`인 항목으로 남겼습니다. 자동 삭제하지 않았습니다. 요청 메서드·상태 코드와 자체 테스트 결과만 담은 보고서는 Git 제외된 `.local/drive-live-result.json`에 보관했습니다. Client Secret, 비밀번호, 인증 코드, 액세스 토큰을 수집·출력·문서화하지 않았습니다. `.env.local`, 검증 브라우저 프로필 및 로컬 백업도 Git에서 제외되어 있습니다. main 병합·원격 푸시·Production 배포는 수행하지 않았습니다.

## 이전 기록: drive.file 실제 연결 준비

사용자가 Google Cloud에 설정한 `drive.file`과 기존 코드의 `drive.appdata`가 달라 기본 모드를 일반 Drive의 `IdeaDock` 폴더로 변경했습니다. 앱 식별자에 의한 폴더 검색·재사용, 폴더 내부 파일 조회, 사전 발급 ID를 이용한 폴더 생성 재시도, 기존 appDataFolder 호환 옵션, 저장 영역별 캐시·업로드 체크포인트 분리를 추가했습니다.

타입 검사, 기존 단위·회귀 49개 및 모의 OAuth/Drive 브라우저 4개가 통과했습니다. 모의 테스트는 drive.file 요청, 일반 Drive 공간 사용, 폴더 하나 생성·재사용, 파일의 부모 폴더, 반복 이전 및 별도 브라우저에서 이미지·서식 재조회를 검사합니다.

준비 시점에는 로컬 `.env.local`을 Git 제외 상태로 만들고 `http://localhost:3000`에 개발 서버를 시작한 상태였습니다. 당시에는 실제 로그인을 완료하지 않았습니다. 이후 실제 연결 결과는 이 문서 맨 위의 완료 기록을 따릅니다. 검증용 브라우저는 별도 프로필이므로 이 프로필의 빈 체험 저장소로 다른 브라우저에 데이터가 없다고 판단하지 않습니다.

자동 저장 테스트는 진행 중인 저장 이후의 추가 입력 보존, 저장 실패 후 재접속 복구, 오래된 조회 응답 무시, 동시 편집 충돌 시 복사본 보존, 계정 변경 시 화면 데이터 분리와 늦은 업로드 결과 차단을 검사합니다.

DB 테스트는 **마이그레이션 원본**을 PGlite PostgreSQL 엔진에 실행합니다. `auth.uid()`, 인증 역할, Storage 기본 테이블만 테스트용으로 구성하고, 앱 테이블/RPC/RLS/제약/트랜잭션은 실제 SQL을 그대로 사용합니다. 5개 테이블의 다른 사용자/비인증 접근, 교차 사용자 수정·삭제·첨부 차단, 이미지 폴더 소유권, 버전 충돌, 잘못된 URL 저장 시 전체 롤백을 검증했습니다.

## 실행하지 않은 외부 검증

다음 항목은 IdeaDock 전용 Supabase/Vercel 프로젝트와 실제 인증 설정이 없어 실행하지 않았습니다. 완전한 v0.1 운영 검증이 끝났다는 의미가 아닙니다.

- Google OAuth 실제 동의/리디렉션 및 로그아웃
- Supabase 운영 API와 실제 Storage 업로드·다운로드·서명 URL·MIME/크기 제한
- 두 실제 기기에서의 동기화와 동시 편집
- Vercel 배포 후 실제 URL에서의 사용 흐름
- Safari/WebKit 실기기 및 수동 스크린 리더 검사

`npm run test:security`는 실행했지만 환경변수 미설정으로 **NOT RUN / 종료 코드 2**를 반환했습니다. 이는 통과로 집계하지 않았습니다. 전용 프로젝트 연결 후 `docs/SETUP.md`에 따라 실제 API 검증을 실행해야 합니다.

소스는 이후 GitHub main에 업로드했습니다. 원격 CI와 실제 서비스 연결 진행 상황은 [RELEASE.md](RELEASE.md)에 별도로 기록합니다.

## 발견 후 해결한 문제

- 옅은 배경 위 보조 텍스트 대비가 4.33~4.35:1로 측정됨 → 보조 색상을 조정하고 라이트/다크 axe 검사를 통과함.
- 오래된 초기 조회가 새 저장 결과를 지울 가능성 → 조회 시작 이후 상태가 바뀌면 응답을 적용하지 않도록 수정하고 회귀 테스트 통과.
- 저장 중 추가 입력이 이전 응답으로 덮일 가능성 → 변경 순번과 서버 버전을 따로 반영하고 회귀 테스트 통과.
- 첨부가 있는 충돌 복사본이 원본 링크/이미지 ID와 경로를 재사용함 → 새 ID와 비공개 Storage 복사 경로를 만들고 본문 이미지 참조도 갱신하도록 수정. 복사 실패 시 원본 초안 유지 테스트 포함 2개 추가 통과. 실제 Storage COPY API는 연결 후 확인 필요.
- 계정 전환 후 늦게 완료된 작업이 새 계정 초안에 섞일 가능성 → 업데이트 시 현재 사용자 소유권을 재검사하고 회귀 테스트 통과.
- 테스트가 링크 이름과 고정 버튼을 잘못 선택함 → 실제 접근 가능한 이름과 article 범위로 locator를 수정함.
- Windows PowerShell 실행 정책과 sandbox의 esbuild 경로 접근 제한 → `npm.cmd` 및 허용된 실행 권한으로 검증함. 시스템 실행 정책은 변경하지 않음.
