테스트된 흐름은 제목 한 줄 생성, 본문 자동 저장·새로고침 복구, 완료 체크와 가독성 유지, 태그/본문 검색, 링크 추가·새 탭, 휴지통 이동·복원, 이미지 업로드·붙여넣기·본문 표시·확대·삭제, 브라우저 뒤로 가기, 패널 크기 키보드 조절·접기·설정 복원, 테마 변경·기억입니다.

자동 저장 테스트는 진행 중인 저장 이후의 추가 입력 보존, 저장 실패 후 재접속 복구, 오래된 조회 응답 무시, 동시 편집 충돌 시 복사본 보존, 계정 변경 시 화면 데이터 분리와 늦은 업로드 결과 차단을 검사합니다.

DB 테스트는 **마이그레이션 원본**을 PGlite PostgreSQL 엔진에 실행합니다. `auth.uid()`, 인증 역할, Storage 기본 테이블만 테스트용으로 구성하고, 앱 테이블/RPC/RLS/제약/트랜잭션은 실제 SQL을 그대로 사용합니다. 5개 테이블의 다른 사용자/비인증 접근, 교차 사용자 수정·삭제·첨부 차단, 이미지 폴더 소유권, 버전 충돌, 잘못된 URL 저장 시 전체 롤백을 검증했습니다.

## 실행하지 않은 외부 검증

다음 항목은 IdeaDock 전용 Supabase/Vercel 프로젝트와 실제 인증 설정이 없어 실행하지 않았습니다. 완전한 v0.1 운영 검증이 끝났다는 의미가 아닙니다.

- Google OAuth 실제 동의/리디렉션 및 로그아웃
- Supabase 운영 API와 실제 Storage 업로드·다운로드·서명 URL·MIME/크기 제한
- 두 실제 기기에서의 동기화와 동시 편집
- Vercel 배포 후 실제 URL에서의 사용 흐름
- Safari/WebKit 실기기 및 수동 스크린 리더 검사

`npm run test:security`는 실행했지만 환경변수 미설정으로 **NOT RUN / 종료 코드 2**를 반환했습니다. 이는 통과로 집계하지 않았습니다. 전용 프로젝트 연결 후 `docs/SETUP.md`에 따라 실제 API 검증을 실행해야 합니다.

소스는 이후 GitHub main에 업로드했습니다. 원격 CI와 실제 서비스 연결 진행 상황은 [RELEASE.md](RELEASE.md)에 별도로 기록합니다.

## 발견 후 해결한 문제

- 옅은 배경 위 보조 텍스트 대비가 4.33~4.35:1로 측정됨 → 보조 색상을 조정하고 라이트/다크 axe 검사를 통과함.
- 오래된 초기 조회가 새 저장 결과를 지울 가능성 → 조회 시작 이후 상태가 바뀌면 응답을 적용하지 않도록 수정하고 회귀 테스트 통과.
- 저장 중 추가 입력이 이전 응답으로 덮일 가능성 → 변경 순번과 서버 버전을 따로 반영하고 회귀 테스트 통과.
- 첨부가 있는 충돌 복사본이 원본 링크/이미지 ID와 경로를 재사용함 → 새 ID와 비공개 Storage 복사 경로를 만들고 본문 이미지 참조도 갱신하도록 수정. 복사 실패 시 원본 초안 유지 테스트 포함 2개 추가 통과. 실제 Storage COPY API는 연결 후 확인 필요.
- 계정 전환 후 늦게 완료된 작업이 새 계정 초안에 섞일 가능성 → 업데이트 시 현재 사용자 소유권을 재검사하고 회귀 테스트 통과.
- 테스트가 링크 이름과 고정 버튼을 잘못 선택함 → 실제 접근 가능한 이름과 article 범위로 locator를 수정함.
- Windows PowerShell 실행 정책과 sandbox의 esbuild 경로 접근 제한 → `npm.cmd` 및 허용된 실행 권한으로 검증함. 시스템 실행 정책은 변경하지 않음.
