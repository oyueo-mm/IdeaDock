# IdeaDock v0.2 — folders, explorer selection, and Word import

## Data and compatibility

- Existing `Idea` records keep their IDs, content, timestamps and revision bytes. `folder_id?: string | null` and `imports?: {file_hash, item_id}[]` are optional; old records are not normalized or rewritten when read. Missing `folder_id` means unclassified/root.
- A logical `Folder` has `id`, `user_id`, `name`, `parent_id`, `created_at`, `updated_at`, `deleted_at`, and `version`. Iterative ancestry checks reject cycles, missing parents, cross-account references, and moves into trash. Deep trees cap visual indentation and scroll breadcrumbs without limiting the data depth.
- Logical folders use immutable `folder-revision` files in the existing physical IdeaDock Drive folder. Their payloads have a hash, revision parent, optional merged sibling hashes, and a folder record. Existing `revision` files and their SHA-256 algorithm are unchanged. The app never rearranges physical Drive folders to match logical folders.
- Folder drafts, heads and pending revisions use account-scoped IndexedDB (`${driveCacheKey(account)}:folders:v2`). Demo folders use `ideadock:folders:demo:v2`; the established demo idea cache remains readable. A per-account write gate prevents idea revisions from uploading ahead of pending folder changes.
- Concurrent folder edits keep their immutable alternatives and drafts. Explicit root repair keeps recovered versions as copies; no original revisions are deleted. Concurrent moves creating a parent cycle are reported, not silently accepted.
- Deleting a folder hides its descendants through inherited trash state without rewriting their IDs, contents or timestamps. Restoration preserves hierarchy. Restoring an item requiring a deleted ancestor asks before restoring that ancestor and its contents. Permanent deletion is not offered.
- Backups with folders use `ideadock-migration-v2`; the existing v1 format and its checksum remain readable. Both include source snapshots and image checksums; v2 also includes complete folder hierarchies and memberships. Divergent duplicate IDs fail validation. Empty folders can be backed up and restored. Legacy discovery, approval, recovery-download confirmation, idempotent migration and image reread verification remain available.

## Explorer interactions

The existing three panels, resize handles, collapse controls, steel blue theme, editor, tags and first-image thumbnails remain. The sidebar contains the folder tree; the center lists the current folder's children and ideas with clickable breadcrumbs. Global filters still show ideas across folders.

- Click an idea to edit; Ctrl/Cmd-click toggles selection, Shift-click selects a range, and a rectangle dragged from empty list space selects intersecting rows. Ctrl-drag rectangles toggle against the starting selection.
- Double-click or Enter opens a folder. Context menus provide applicable open/rename/move/completion/pin/trash/restore actions. The right panel shows batch actions for multiple items or selected folders.
- Drag selected items to a center folder, sidebar tree folder, or root. The app shows counts, target and validity, expands hovered folders, and scrolls near edges. An ancestor and its selected descendants move as a hierarchy. Invalid self/descendant/cross-account/trash moves are rejected in the domain layer too.
- Ctrl/Cmd+A, Delete, F2 and Escape apply in explorer areas. Text inputs and the editor retain their own keys; Ctrl+N/Ctrl+T are not intercepted.
- Mobile uses long press, tap selection, and an explicit move picker. HTML touch dragging is disabled to preserve scrolling. Mouse-only and touch-only browser tests run on their respective projects.

## Word import

Use **Data management → Word import** to choose a `.docx`. Parsing is entirely in the browser (`fflate` ZIP extraction and XML traversal); no server or AI rewriting is involved. Headings, short bold titles, numbered titles and textual separators are candidate boundaries. Description paragraphs stay together until a detected boundary. Ambiguous sections stay together with a review warning.

The preview preserves order, paragraph/text content, supported emphasis, actual hyperlinks, embedded image bytes and matching Tiptap image references. It supports selecting/excluding entries, titles, folder selection, completion, duplicate decisions, splitting at a displayed paragraph and merging adjacent candidates. Completion defaults to false. Categories are never guessed. PNG/JPEG/WebP/GIF up to 5MB and 12 attachments per idea follow the existing limits. Unsupported images, external images and unrecognized references are warnings requiring acknowledgement; the original DOCX bytes remain in the import backup rather than silently disappearing.

Duplicate candidates use normalized titles, text similarity, file hashes and item source history. Existing records are skipped by default where appropriate. Adding uses deterministic IDs; merging requires a separate explicit checkbox and appends the original content/images while keeping the existing title, folder, completion and pin state. No existing record is automatically overwritten.

Approval creates and rereads a complete current-workspace recovery backup and a separate source/import backup containing the original DOCX, candidates and image bytes. Backups reach Drive before ideas. Pending changes or stale remote snapshots block importing. Plans and progress are account-scoped in IndexedDB; failed or lost upload replies can be retried with stable hashes/IDs. Every uploaded document and image is reread and checked. Closing/reloading can resume from the saved preview. The source file is never modified or deleted.

File limits are 25MB compressed, 20MB per decompressed ZIP member and 100MB total. Complex Word page/table layout, external included documents and unsupported drawing formats are not reproduced; visible warnings and manual split/merge review are required. This is source-preserving structural import, not an Office layout renderer.
